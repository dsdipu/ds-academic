# Time Management in Exams

<LastUpdated date="2026-05-22" timeTo="30 minutes" difficulty="Beginner" />

## 📌 Quick Summary (30 seconds)

**The golden rule:** Allocate **1.5 minutes per mark**. A 3-hour exam with 100 marks = 180 minutes total = 1.8 minutes per mark. Start with questions you're confident about. Never spend more than your allocated time on one question — leave it and return.

---

## 📚 Time Allocation Formula

```
Total time  ÷  Total marks  =  Minutes per mark

3 hours (180 min) ÷ 100 marks = 1.8 min/mark

For each question:
  Marks × 1.8 = Allocated time

Examples:
  3-mark question  → 3 × 1.8 = 5–6 minutes
  5-mark question  → 5 × 1.8 = 8–9 minutes
  8-mark question  → 8 × 1.8 = 14–15 minutes
  10-mark question → 10 × 1.8 = 18 minutes
```

## 📋 Exam Strategy: Step by Step

### Before Writing Anything (5 minutes)

1. Read ALL questions quickly
2. Mark questions as: ✅ Easy (do first), ⚠️ Medium (do second), ❌ Hard (do last)
3. Plan time: write start time for each question on your paper
4. Check total marks and confirm your time budget

### Order of Attempt

**Round 1 — Easy questions first (50–60% of time)**
- Answer everything you're confident about
- Full marks on easy questions > partial marks on hard ones
- Builds momentum and confidence

**Round 2 — Medium questions (30–35% of time)**
- Apply your knowledge systematically
- If stuck, write what you know — partial credit exists

**Round 3 — Hard/uncertain questions (remaining time)**
- Attempt ALL questions — never leave blank
- Partial marks: even a definition gets 1 mark

### During Each Question

```
Step 1: Read twice (30 sec)
Step 2: Note key words — "explain", "compare", "write code", "draw"
Step 3: Bullet-plan your answer (30 sec)
Step 4: Write structured answer
Step 5: Check against mark allocation — enough points?
```

---

## ⚠️ Time Traps to Avoid

### Trap 1: Perfectionism on Easy Questions
You don't need a perfect answer — you need a complete answer. A 3-mark question needs 3 points, not a 2-page essay.

### Trap 2: Getting Stuck and Staying Stuck
**Rule:** If you're stuck for more than 2 minutes on any question, SKIP and return later. Coming back with fresh eyes almost always helps.

### Trap 3: No Time for Code Questions
Code questions take longer. Budget **2 minutes per mark** for code-writing questions.

### Trap 4: Forgetting to Attempt All Questions
Even a partial attempt gets partial marks. "I don't know" gets zero. An attempt — however incomplete — gets something.

| Section | Marks | Time | Strategy |
|---------|-------|------|----------|
| MCQs (20 × 1) | 20 | 25 min | Fast — 1.25 min each |
| Short answers (5 × 5) | 25 | 40 min | 8 min each |
| Code questions (2 × 10) | 20 | 35 min | 17 min each |
| Long answer (1 × 15) | 15 | 25 min | PEEL structure |

| **Buffer** | — | 20 min | Review + stuck Qs |
| **Total** | **100** | **180 min** | |

## 🎯 Subject-Specific Tips

### HTML/CSS Questions
- Draw diagrams quickly — box model, flexbox axes save words and score marks
- Write code in blocks — don't inline everything
- Always add DOCTYPE and proper structure even for small snippets

### JavaScript Questions
- For "predict output" questions — trace through line by line on paper
- Always test your logic with a simple example before writing

### Docker Questions
- The Docker vs VM comparison table is worth memorising cold
- Write Dockerfile instructions in order — they must be sequential

## 👨‍🏫 From a Student's Perspective

The mistake that cost me most marks in my first CSE exam: spending 25 minutes on a 5-mark question because I wanted to write the "perfect" answer. I ran out of time on a 10-mark question I knew perfectly.

**The mindset shift:** An exam is not a test of how much you know. It's a test of how efficiently you can demonstrate what you know in a limited time. Efficiency is a skill, and it's learned by practicing under time constraints.

**My personal rule:** Set an alarm on my watch for the allocated time per question. When it goes off, I write one more line and move on.
